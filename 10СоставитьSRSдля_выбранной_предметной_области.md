## 1. Введение

### 1.1. Назначение

Настоящий документ описывает **полный набор требований** к информационной системе управления кадровым агентством «КадрПро». Документ предназначен для:
- заказчика — для согласования объёма работ;
- команды разработки — как основа для проектирования и реализации;
- тестировщиков — как основа для проверки.

### 1.2. Область применения

Система предназначена для **автоматизации деятельности кадрового агентства**:
- учёт соискателей и их резюме;
- учёт вакансий от предприятий;
- подбор подходящих вакансий для соискателей;
- фиксация результатов трудоустройства;
- формирование отчётности для налоговых органов и органов статистики.

## 2. Общее описание

### 2.1. Перспектива продукта

Система **заменяет** ручной учёт данных о соискателях и вакансиях (Excel-таблицы, бумажные карточки, разрозненные файлы) **единой информационной системой** с централизованной базой данных.

### 2.2. Функции продукта

- **Учёт соискателей** — регистрация, хранение резюме, классификация.
- **Учёт вакансий** — приём от предприятий, актуализация.
- **Подбор** — сопоставление резюме и вакансий.
- **Трудоустройство** — фиксация факта закрытия вакансии.
- **Отчётность** — для налоговых органов и статистики.
- **Администрирование** — права доступа, резервное копирование.

### 2.3. Характеристики пользователей

| Пользователь | Роль |
|---|---|
| **Специалист по подбору (рекрутер)** | Работа с соискателями и вакансиями |
| **Менеджер по работе с работодателями** | Приём заявок от предприятий |
| **Бухгалтер** | Формирование налоговой и статистической отчётности |
| **Руководитель** | Контроль работы, просмотр отчётов |
| **Администратор** | Управление пользователями, резервное копирование |
| **Соискатель** (внешний) | Подача резюме через форму |
| **Работодатель** (внешний) | Передача данных о вакансиях |

### 2.4. Ограничения

- Работа в **локальной сети** с выходом в интернет.
- Соответствие **152-ФЗ** «О персональных данных».
- Веб-интерфейс, работа через браузер.
- Русскоязычный интерфейс.

### 2.5. Предположения и зависимости

- Предприятия предоставляют данные о вакансиях в электронном виде.
- Пользователи имеют базовые навыки работы с браузером.
- Сервер доступен круглосуточно.

## 3. Конкретные требования

### 3.1. Функциональные требования

#### ФТ-1. Регистрация соискателя

**Описание:** система должна позволять регистрировать нового соискателя с указанием персональных данных и контактной информации.

**Входные данные:** ФИО, дата рождения, телефон, email, образование, специальность, опыт работы.

**Выходные данные:** запись в базе данных, уникальный ID соискателя.

**Приоритет:** Must have.

---

#### ФТ-2. Ведение резюме

**Описание:** соискатель или рекрутер должен иметь возможность создавать, редактировать и удалять резюме.

**Входные данные:** желаемая должность, желаемая зарплата, ключевые навыки, дополнительная информация.

**Выходные данные:** резюме, привязанное к соискателю.

**Приоритет:** Must have.

---

#### ФТ-3. Регистрация вакансии

**Описание:** система должна позволять регистрировать вакансии от предприятий.

**Входные данные:** название организации, ИНН, должность, требования, зарплата (от–до), график работы.

**Выходные данные:** запись в базе данных, статус «открыта».

**Приоритет:** Must have.

---

#### ФТ-4. Подбор кандидатов

**Описание:** система должна автоматически сопоставлять резюме с вакансиями по ключевым параметрам.

**Входные данные:** параметры вакансии, база резюме.

**Выходные данные:** список подходящих кандидатов с оценкой соответствия.

**Приоритет:** Must have.

---

#### ФТ-5. Назначение на вакансию

**Описание:** рекрутер должен иметь возможность назначать соискателя на вакансию.

**Входные данные:** ID соискателя, ID вакансии, статус (предложено / собеседование / трудоустроен / отказ).

**Выходные данные:** запись о назначении, изменение статуса вакансии.

**Приоритет:** Must have.

---

#### ФТ-6. Фиксация трудоустройства

**Описание:** система должна фиксировать факт трудоустройства соискателя и закрытия вакансии.

**Входные данные:** ID назначения, дата трудоустройства.

**Выходные данные:** статус соискателя — «трудоустроен», статус вакансии — «закрыта».

**Приоритет:** Must have.

---

#### ФТ-7. Формирование отчётности

**Описание:** система должна формировать отчёты для налоговых органов и органов статистики.

**Входные данные:** данные о трудоустройствах, платежах, отчислениях.

**Выходные данные:** отчёт в формате, установленном законодательством.

**Приоритет:** Must have.

---

#### ФТ-8. Поиск и фильтрация

**Описание:** система должна обеспечивать поиск и фильтрацию по соискателям и вакансиям.

**Входные данные:** критерии поиска (профессия, опыт, зарплата, район).

**Выходные данные:** список записей, удовлетворяющих критериям.

**Приоритет:** Should have.

---

#### ФТ-9. Разграничение прав доступа

**Описание:** система должна обеспечивать разграничение прав доступа по ролям.

**Роли:** администратор, рекрутер, менеджер, бухгалтер, руководитель.

**Приоритет:** Must have.

---

#### ФТ-10. Уведомления

**Описание:** система должна отправлять уведомления соискателям и работодателям.

**Каналы:** email, SMS.

**Приоритет:** Could have.

---

### 3.2. Нефункциональные требования

#### НФТ-1. Производительность

- Время отклика системы — **не более 3 секунд** на стандартные запросы.
- Поиск по базе (до 100 000 записей) — **не более 5 секунд**.
- Одновременная работа — **не менее 50 пользователей**.

**Приоритет:** Must have.

---

#### НФТ-2. Надёжность

- Доступность системы — **не менее 99,5%** в год.
- Время восстановления после сбоя — **не более 30 минут**.
- Резервное копирование БД — **ежедневно** (полное), **ежечасно** (инкрементальное).

**Приоритет:** Must have.

---

#### НФТ-3. Безопасность

- Шифрование данных при передаче — **TLS 1.3**.
- Хранение паролей — **bcrypt** или **Argon2**.
- Разграничение доступа по ролям.
- Журналирование действий пользователей.
- Соответствие **152-ФЗ** «О персональных данных».

**Приоритет:** Must have.

---

#### НФТ-4. Удобство использования

- Веб-интерфейс, адаптированный для ПК и мобильных устройств.
- Интуитивно понятный интерфейс.
- Обучение нового пользователя — **не более 2 часов**.
- Поддержка **русского языка**.

**Приоритет:** Should have.

---

#### НФТ-5. Масштабируемость

- Горизонтальное масштабирование при росте нагрузки.
- Поддержка увеличения объёма данных до **1 000 000 записей** без потери производительности.
- Модульная архитектура для добавления новых функций.

**Приоритет:** Should have.

---

#### НФТ-6. Совместимость

- Поддержка браузеров: **Chrome, Firefox, Safari, Edge** (последние версии).
- Работа на ОС: **Windows, Linux, macOS**.
- Интеграция с внешними системами через **API**.

**Приоритет:** Should have.

---

### 3.3. Требования к внешним интерфейсам

#### 3.3.1. Пользовательский интерфейс

- Веб-браузер.
- Личный кабинет для соискателя и работодателя.
- Панель администратора.

#### 3.3.2. Программный интерфейс

- REST API для интеграции с внешними сервисами.
- Формат данных — **JSON**.

#### 3.3.3. Аппаратный интерфейс

- Сервер с 8 ГБ ОЗУ, 4 ядра CPU, 256 ГБ SSD.
- Клиентские устройства с браузером.

#### 3.3.4. Коммуникационный интерфейс

- Протоколы: **HTTPS**, **SMTP** (для email), **SMPP** (для SMS).
